# Repository audit (2026-10-20)

What the repository actually contains, and what that means for the production design.

## Applications

| Area | Finding | Location |
|---|---|---|
| Frontend | Next.js 16 / React 19 / TypeScript. Client-side app; calls the API directly from the browser using `NEXT_PUBLIC_API_BASE_URL`, which is baked in at build time. No server-side API routes. | `app/`, `components/`, `lib/` |
| Frontend tests | `tsc` typecheck, `tsx --test` unit tests, Playwright e2e (against the built-in demo workspace). No ESLint configuration. | `tests/`, `playwright.config.ts` |
| Frontend container | Multi-stage Node 24 Alpine image, `npm start` (`next start`), runs as `node`. Honours `PORT`. | `Dockerfile` |
| Backend | Python 3.12, FastAPI + Pydantic v2, SQLAlchemy 2. ASGI entry point `beeproof.api.app:app`. All routes under `/api/v1`, plus `/healthz`. | `backend/beeproof/api/app.py` |
| Document pipeline | Triage (PyMuPDF / Pillow / OpenCV) → Witness A (PyMuPDF words or Document AI) → Witness B (Gemini or offline text-layer parser) → schema map → reconcile → validators → bounded re-look → scoring. CPU- and model-bound; typically seconds per page. | `backend/beeproof/pipeline/` |
| Background work | Job state machine in the database; workers claim jobs atomically. Previously a long-running polling loop (`python -m beeproof.worker`) with optional Redis wake-ups. **Added:** an HTTP worker for push delivery (`beeproof.worker_http:app`). | `backend/beeproof/worker*.py` |
| Agent orchestration | Explicit state machine, not a free-roaming agent. LLM calls happen only in Witness B and the re-look step. | `backend/beeproof/pipeline/orchestrator.py` |
| Evaluation | Synthetic benchmark generator and evaluator. Previously run in an API background thread. **Changed:** dispatched to the worker via Cloud Tasks in production. | `backend/bench/`, `services/evaluation.py` |

## Data and storage

| Topic | Finding | Production impact |
|---|---|---|
| Database | SQLAlchemy models with JSON columns. Tables were created with `create_all` at startup; **no migration tool existed**. | **Added** Alembic (`beeproof/migrations`), a baseline `0001_initial` autogenerated from PostgreSQL, and `python -m beeproof.migrate`. The runner holds an advisory lock, adopts existing `create_all` databases, and grants the runtime role data-only access. `AUTO_CREATE_TABLES=false` in production. |
| Files | Storage adapter: local disk or GCS (`STORE=gcs`). Keys are generated server-side. Previews, crops and exports are streamed through the API. | One private bucket with prefixes. No public objects. |
| Uploads | Signature sniffing, extension/MIME match, 20 MB limit, page and pixel limits, path-safe display names. | Unchanged. Cloud Run's 32 MiB request limit is above the 20 MB app limit. |

## Runtime dependencies

| Dependency | Finding | Production decision |
|---|---|---|
| Redis | Used only in docker compose, for queue wake-ups and the shared rate-limit counter. | Not deployed (Memorystore cost). Cloud Tasks replaces the queue; rate limiting falls back to per-instance limits plus Cloudflare rules. |
| Vertex AI Gemini | `google-genai` client, structured output, tenacity retries on 429/5xx. Model from `GEMINI_MODEL`. | Worker only. Concurrency is bounded by the Cloud Tasks queue (`max_concurrent_dispatches`). |
| Document AI | Form Parser adapter. Optional (`DOCAI_PROCESSOR_ID`). | Worker only. |
| Streaming | No WebSockets or SSE. The frontend polls job status about every 2.5 s. | No sticky sessions or long-lived connections needed. |

## Security posture

| Topic | Finding |
|---|---|
| Authentication / authorization | **None, by explicit product decision** (`beeproof_ai_documentation_pack/ADR/ADR-004-open-access.md`). No organization isolation exists. Anyone who can reach the public hostname can upload, review and export. This deployment does not add auth. Cloudflare Access or WAF rules are the recommended outer controls if needed (see SECURITY.md). |
| CORS | `CORS_ORIGINS`; production is set to `https://proof.beeneural.com` only. |
| Rate limiting | Per-IP limit on mutating requests (Redis-backed when available, in-process otherwise). |
| Secrets | No secrets in source. The DB URL, tunnel token and any provider credentials come from Secret Manager or ADC. |
| Prompt injection | Prompts tell the model to ignore instructions in documents. Outputs are schema-validated, and deterministic validators gate acceptance. |

## Existing CI/CD before this change

- `.github/workflows/frontend.yml` (Codex) ran frontend checks on every push. It is **folded into `ci.yml`**, which runs the same steps plus backend, containers, Terraform and security jobs. The old file was removed to avoid duplicate runs.
- There was no deployment workflow, Terraform or GCP configuration.

## Gaps closed by this change

1. Push delivery to a private worker (Cloud Tasks + OIDC) with idempotent claims, a recovery sweep (Cloud Scheduler) and bounded retries.
2. Controlled, locked, idempotent migrations as a Cloud Run Job.
3. Structured JSON logs with trace and request correlation for Cloud Logging.
4. Connection-pool limits sized for Cloud Run scale-out.
5. Separate `api` and `worker` image targets, both running as non-root.
6. Terraform, CI/CD, Cloudflare Tunnel connector, monitoring and documentation.
